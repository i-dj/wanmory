# Wanmory 功能规划

原始功能清单和三轮评审建议合并后的版本。架构、默认模型、AI 服务接口以 [README](../README.md) 为准，这里只写“做什么、按什么顺序做、有哪些坑”。

状态：✅ 已有　🚧 部分完成　⬜ 计划

## 核心原则

1. **本地优先**：照片和 AI 结果不离开家庭网络。这是宝宝相册最大的卖点。
2. **显示保真是信任问题**：用户看到的必须是他最后看到的那个版本（编辑过的、调过色的）。显示不对，精选、评分、MV 全都会挑错，用户只要见到一次就不再信任。渲染不了的地方要标明“原片”或“近似渲染”，不要给一张似是而非的图。
3. **不接管用户文件**：外部图库原地索引，只读不动；app 产生的星级、标签写回 XMP sidecar，不做数据孤岛。
4. **先出图，后算 AI**：导入后马上能看，AI 任务在后台增量跑，能断点续跑，进度看得见。
5. **破坏性操作必须验证结果**：删除、移动以后检查文件状态，失败就明确报错，不能静默成功。

### 显示保真（按阶段做）

宝宝照片大多是手机拍的 JPEG/HEIC，RAW 的问题基本遇不到，但手机有自己的坑：

| 阶段 | 内容 |
| --- | --- |
| 1. 基本正确 | 正确处理 EXIF 方向；Display P3 等 ICC 色彩配置转换成 sRGB 时不能丢；HEIC 正常解码 |
| 2. 手机编辑 | iCloud/Mac“照片”导出原件时，编辑存在 `.AAE` sidecar 里，没有烧进文件。导出的时候应该选“已修改版本”；如果只有原件，要在界面上标明“原片” |
| 3. HDR | iPhone/Android 的 HDR 增益图（gain map）：先保证 SDR 正确显示，HDR 后面再说 |
| 4. RAW（可选） | 先用内嵌的 JPEG 预览；解析 XMP 里的 `crs:` 参数，只读展示 → 基础调整的近似渲染（标明“近似”）→ 完整保真。解码交给 libraw，不要自己写处理管线 |

### XMP sidecar

- 读取：星级、标签、描述、层级关键词 `lr:hierarchicalSubject`、`crs:` 调色参数
- 写回：app 里改的星级、挑选标记、标签写回 sidecar，Lightroom、群晖都能读到。默认关闭，由用户开启（写文件就是改动用户的文件夹）

## 二、AI 智能整理

默认模型见 README。这里只记功能和需要注意的地方。

| 功能 | 状态 | 方案与坑 |
| --- | --- | --- |
| 人脸检测 + 特征 + 聚类 + 命名 | ⬜ | SCRFD + ArcFace。**只拿正脸、清晰、尺寸够大的脸进聚类**，侧脸和模糊的脸等聚类完成后再按最近的人物原型归类。InsightFace 权重只能非商业使用 |
| 中文语义搜索 | ✅ | 图库上方的搜索框：按照片里的字（OCR）和按内容（AI 看图）一起搜，可以叠加人物、分类、相机、镜头、照片/视频筛选，结果按时间排。Chinese-CLIP（阿里达摩院 OFA-Sys 出品，原生中文）；多语言模型可以选 Jina CLIP v2。比 Immich 默认英文模型强，是差异化亮点 |
| 场景分类 | ✅ | **不单独做模型**，用 CLIP zero-shot，配一套中文标签词表：截图、证件、文档、美食、宠物、风景（见 server/internal/clip） |
| 重复/相似照片 | 🚧 | 「连拍整理」已有：时间窗口 + 人脸质量 + 文件大小挑最好的一张。还没用上 CLIP 向量距离和感知哈希。 完全重复靠哈希（已有）；连拍和相似照片：时间窗口 + CLIP 向量距离 + 感知哈希，一组里推荐保留最好的一张，删除前要用户确认 |
| 最佳照片评分 | ⬜ | 清晰度（拉普拉斯方差）+ 睁眼、笑脸（人脸关键点）+ 美学分（CLIP 上的线性头，比如 LAION aesthetic）。**评分必须用保真的预览图计算** |
| 图片描述 | ⬜ | Qwen3-VL，默认关闭。全量跑用小模型（2B/4B），8B 只给精选和里程碑候选用。不要用 moondream 一类只会英文的模型，中文搜索还得再翻译一道 |
| OCR | ✅ | 现在各平台都用 RapidOCR + PP-OCRv6 small（onnxruntime，CPU 上一张三四百毫秒），认出的字可以搜索，也用来判断证件和文档。之后可以在 Mac 上换 Apple Vision、换 medium 模型；证件类照片可以关闭 OCR |
| 学习用户审美 | ⬜ | 收藏、删除、精选里被替换掉的照片作为反馈，调整评分权重 |

## 三、宝宝成长相册

| 功能 | 说明 |
| --- | --- |
| 宝宝照片识别 | 按月龄段分别建人物原型；靠时间连续性把相邻月份的脸串起来；用户在各个年龄段标注“种子”照片；小孩用更严格的阈值，宁可少归也不要错归 |
| 月龄计算 | 拍摄时间（已做时区修正）− 出生日期，精确到天 |
| 月龄分组 | 新生儿、1–12 个月，之后按季度、半年、年 |
| 每月精选 | 每月挑 N 张，同一场景只取一张，保证多样性 |
| 里程碑识别 | 先由 CLIP 找出候选（蛋糕和蜡烛、海边、洗澡等），再用 Qwen3-VL 复核，**最后由用户确认**。“第一次走路”这类单张照片判断不了，要允许用户手动标记 |
| 月龄相册标题 | 根据确认过的里程碑生成，比如“3 个月：第一次翻身” |
| 成长对比图 | 每月挑一张正脸，按眼睛位置对齐，拼成网格 |
| 成长变脸动画 | 眼睛对齐，一秒一个月 |
| **爸妈小时候同月龄对比** | 导入父母的童年照片（多半是扫描件，没有 EXIF，要手动填年龄），和宝宝同月龄的照片拼在一起。传播性很强 |
| **九宫格导出** | 每月精选自动排成朋友圈九宫格，带月龄水印 |
| **一年前的今天** | 成本很低，打开率很高 |
| **成长小故事** | 用本地小 LLM 根据月龄、里程碑和描述生成每月一段文字，做成绘本卡片 |

## 五、家庭共享与隐私

- 局域网内给爷爷奶奶看：多用户只读账号，或者导出离线 HTML 相册
- 分享时自动模糊其他小朋友的脸（人脸识别现成能用）
- 远程 AI 节点只拿到 1440 像素预览图（README 里已经写明）

## 六、架构要点

已经定下来的不再讨论：**PostgreSQL + pgvector + Docker Compose**。在单用户的规模下，数据库不会是瓶颈，推理速度才是。需要做好的地方：

- **Mac 上 AI 服务要在本机原生运行，不能放进容器**：Docker/OrbStack 容器在 macOS 上用不到 Apple GPU，CoreML 和 MPS 都没有，只能跑 CPU。开发和“NAS + 家里的 Mac”这两种场景，Mac 上都应该直接 `uv run` 跑 AI 服务，或者作为工作节点跑；PostgreSQL 和后端仍然放在容器里
- **推理后端**：CLIP、人脸这类向量模型用 ONNX Runtime + CoreML EP；CLIP 也尽量导出成 ONNX，PyTorch 只留给 VLM、深度模型和视频模型
- **向量索引**：HNSW，从 `m=16, ef_construction=64` 开始；人脸向量和 CLIP 向量分表（CLIP 已经单独建表）
- **单写者**：任务队列 + `SKIP LOCKED` 已经实现；批量导入用 `COPY`，先导入数据再建索引
- **备份**：compose 里加一个定时跑 `pg_dump` 的 sidecar，备份和照片放在一起，并写好恢复步骤，而且要真的演练一遍
- **配置防呆**：设置值要按 schema 校验，null 能容错，改配置前先备份，配置损坏时能恢复，不能静默重建一份空配置
- **UI 留扩展入口**：自定义 CSS/主题，不要逼用户靠注入脚本改界面

## 七、开发顺序

原清单主张先做月龄分组，评审建议先验证人脸聚类。两者可以并行：月龄标签不依赖人脸，而后面的精选和 MV 依赖“哪些是宝宝”。

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| **0. 补地基** | 时间修复 + 时区修正；外部图库原地索引；显示保真第 1 阶段；视频关键帧 | 微信、WhatsApp 保存的图时间正确；P3 色彩照片颜色不偏 |
| **1. 最小闭环** | AI 服务跑通 SCRFD/ArcFace/Chinese-CLIP（Mac 原生运行 + CoreML）；人脸聚类和命名；中文搜索；全库按月龄打标签 | 用 500 张跨 0–24 月龄的宝宝照片实测：宝宝聚类的查准率 ≥ 95%，召回率 ≥ 85%（加上种子照片后）。**这一关过不了，后面就不要往下做** |
| **2. 成长相册** | 质量评分、相似照片去重、每月精选、月龄相册、九宫格导出、一年前的今天 | 每月精选里，用户手动替换的比例 < 30% |
| **3. MV** | Ken Burns + 卡点 + 转场 + 片头片尾 → 2.5D 视差 + 补帧 → 场合模板 | 一年的成长 MV 在 M 系列 Mac 上 10 分钟内生成 |
| **4. 进阶** | 里程碑（候选 + 用户确认）、成长对比图和变脸动画、父母童年照对比、图片描述、OCR、成长小故事、家庭共享、XMP 写回、RAW 显示 | |
| **5. 可选** | AI 图生视频（只在显卡节点上跑）、审美模型微调 | |
